# Repository Instructions

## Instruction File Language

- Write all instructions, rules, section headings, labels, examples, and other prose added to `AGENTS.md` in English.
- This English-only rule applies to repository-level agent instructions and does not change the required language of user-facing documents or outputs generated by skills.

## Skill Source Language

- Write and maintain every skill source file in English.
- This includes `SKILL.md` files, skill metadata, agent configuration, templates, examples, and instructional prose shipped with a skill.
- Do not translate skill source files into the user's language.

## Required Language Rule in Every Skill

- Every `SKILL.md` must contain an explicit output-language section or equivalent instruction with this rule: all user-facing output and every document, prompt, report, plan, specification, or other artifact produced by the skill must use the language requested by the user; if no language is specified, use the language of the user's request.
- When creating or modifying a skill, add or update this rule in that skill's `SKILL.md`; do not rely on `AGENTS.md` alone.
- The rule applies to generated prompt text as well as ordinary documents and final responses.

## Generated Documents and Outputs

- When a skill creates, updates, or presents a document, prompt, report, plan, specification, or other user-facing output, write it in the language requested by the user.
- If the user does not explicitly request a language, use the language of the user's request.
- Apply this rule to all user-facing prose, section headings, subsection headings, labels, tables, checklists, diagrams, and templates generated at runtime.
- A skill's English source text is an instruction language only; it must not force generated documents or outputs to be English.

## Sections and Labels

- Preserve the required semantic sections and their order when a skill specifies a document or handoff structure.
- Translate section names and labels into the user's requested language while preserving their meaning and order.
- Do not emit English section names merely because the corresponding semantic slots are named in an English skill source file.

## Technical Tokens

- Preserve code, commands, file paths, identifiers, API names, model IDs, protocol names, and required proper names exactly unless the user explicitly asks for translation.
- Keep Markdown structure and code blocks valid after translating surrounding prose.
