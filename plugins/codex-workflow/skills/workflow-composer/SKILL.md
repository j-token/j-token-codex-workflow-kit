# 워크플로우 컴포저

## 출력 언어

사용자가 출력 언어를 명시적으로 지정하면 해당 언어를 사용합니다. 지정하지 않으면 이 스킬이 만드는 모든 사용자 대상 출력, 문서, 프롬프트, 보고서, 계획, 스펙 및 기타 산출물을 한국어로 작성합니다. 제목, 섹션, 레이블, 표, 체크리스트, 다이어그램과 템플릿에도 같은 언어를 사용합니다. 코드, 명령어, 파일 경로, 식별자, API 이름, 모델 ID, 프로토콜 이름과 필수 고유명사는 번역하지 않습니다.

## 라우팅

| 단서 | 적용 모듈 |
| --- | --- |
| 배경, 목표, 제품·기능 요구사항, 조사와 계획 | `setup-codex-prompt` + `requirements-to-spec` |
| 증상, 오류, 로그, 재현, "안 된다" | `bug-report-to-fix` |
| Figma 링크, 화면, 디자인, 시각 자료 | `figma-flow-to-implementation` |

한 요청에 여러 단서가 있으면 필요한 모듈을 함께 적용합니다. 단일 유형을 고르라고 사용자에게 되묻지 않습니다.

## 공통 흐름

1. 사용자가 부딪힌 순서대로 작업 단위를 식별합니다.
2. `setup-codex-prompt`의 `빠른 작업`, `계획 작업`, `민감 작업` 등급을 적용합니다.
3. 빠른 작업은 현재 요청을 실행 권한으로 보고 같은 작업에서 조사·수정·검증합니다.
4. 계획·민감 작업은 모든 모듈의 사실, 조건, 결정과 실행 계획을 `.codex/prompts/active/<slug>.md` 하나에 기록합니다.
5. 모듈마다 PRD, 기술 스펙, 버그 리포트, UI 문서를 자동 생성하지 않습니다. 프롬프트 문서의 관련 섹션으로 합칩니다.
6. 별도 Codex 작업이 필요하면 프롬프트 문서에서 계획, 모델, 추론 강도, 사유와 실행 프롬프트를 함께 제시합니다.
7. 사용자가 계획과 새 작업 시작을 승인하면 `start-implementation-thread`를 적용합니다.

## 질문 순서

저장소·공식 자료로 답할 수 있는 내용은 먼저 조사합니다. 사용자 판단이 필요한 질문만 사용자가 제시한 작업 순서대로 묻습니다. 한 답으로 여러 모듈이 풀리면 중복 질문을 만들지 않습니다.

## 보조 문서

사용자가 별도 문서 형식을 명시하거나 외부 표준이 요구하는 경우에만 `prd-writer`, `technical-spec-writer`, `audit-technical-spec`, `prototype-design`을 추가합니다. 보조 문서는 프롬프트 문서에서 링크하며 실행 상태를 중복 기록하지 않습니다.

## 핵심 규칙

- 사실, 추정, 조건, 결정, 열린 질문과 제외 방향을 분리합니다.
- 빠른 작업에는 문서 승인, 새 작업 생성과 독립 감사를 강제하지 않습니다.
- 문서 작성과 검토를 이유로 현재 턴을 자동 종료하지 않습니다.
- 동일한 작업의 초안 파일을 버전별로 늘리지 말고 같은 프롬프트 문서를 갱신합니다.
- 외부·비가역 행동의 승인은 해당 행동 직전에 받습니다.
- 새 작업 생성 승인은 계획·모델·추론 강도·프롬프트를 한 묶음으로 한 번 받습니다.
