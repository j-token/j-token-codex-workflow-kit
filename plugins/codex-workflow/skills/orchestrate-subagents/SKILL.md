# 하위 에이전트 조율

## 출력 언어

사용자가 출력 언어를 명시적으로 지정하면 해당 언어를 사용합니다. 지정하지 않으면 이 스킬이 만드는 모든 사용자 대상 출력, 문서, 프롬프트, 보고서, 계획, 스펙 및 기타 산출물을 한국어로 작성합니다. 제목, 섹션, 레이블, 표, 체크리스트, 다이어그램과 템플릿에도 같은 언어를 사용합니다. 코드, 명령어, 파일 경로, 식별자, API 이름, 모델 ID, 프로토콜 이름과 필수 고유명사는 번역하지 않습니다.

## 생성 판단

다음 질문이 모두 참일 때만 하위 에이전트를 만듭니다.

1. 현재 단계에 동시에 진행 가능한 독립 작업이 둘 이상인가?
2. 각 작업의 입력, 완료 조건과 수정 허용 파일을 분리할 수 있는가?
3. 조정 비용보다 시간 단축이나 독립 검증 이점이 큰가?

사용자가 하위 에이전트를 명시적으로 요청한 경우에도 독립 작업이 없으면 0명을 유지하고 이유를 설명합니다. 설명, 상태 확인, 한 파일의 국소 수정은 기본적으로 루트가 수행합니다.

## 위험 기반 독립 검토

독립 검토는 다음 경우에 권장합니다.

- 보안, 개인정보, 결제, 데이터 마이그레이션
- 공개 API·프로토콜·호환성 경계 변경
- 재현이 어렵고 실패 비용이 큰 버그
- 여러 시스템의 계약을 동시에 바꾸는 구현
- 사용자가 독립 검토를 요청함

빠른 작업과 일반 저위험 구현에 구현 전·후 하위 에이전트 검토를 필수로 넣지 않습니다. 도구 부재만으로 이런 작업을 차단하지 않습니다.

## 프롬프트와 컨텍스트

- 기본 `fork_turns`는 `none`입니다. 필요한 원본 문서, 경로, diff와 검증 결과를 프롬프트에 직접 넣습니다.
- 대화 전체, 루트의 예상 결론과 정답을 전달하지 않습니다.
- 읽기 전용 검토에는 `수정 허용 파일: 없음`, `수정 금지 파일: 모든 파일`을 명시합니다.
- 구현 역할에는 서로 겹치지 않는 수정 허용 파일 집합과 검증 명령을 줍니다.
- 모델 override는 현재 협업 도구가 지원하는 모델만 사용하고, override가 있으면 전체 대화를 fork하지 않습니다.

## 결과 검증

루트는 하위 에이전트의 결론을 그대로 전달하지 않습니다.

1. 주장과 `path:line`, 로그, 테스트 또는 공식 자료 근거를 대조합니다.
2. 파일 소유권 위반과 서로 충돌하는 변경을 확인합니다.
3. 유효한 발견만 현재 구현이나 프롬프트 문서에 반영합니다.
4. 변경 후 관련 검증을 다시 실행합니다.
5. 실패한 선택 위임은 루트가 보완할 수 있습니다. 사용자가 명시적으로 요구한 독립 검토가 실패한 경우에는 독립 검토가 완료되지 않았다고 알립니다.

## 판정 계약

독립 검토 결과는 `통과`, `수정 필요`, `차단` 중 하나와 근거를 포함합니다. 발견에는 ID, 심각도, 근거, 영향과 권고가 있어야 합니다. 스타일과 선택적 개선을 차단으로 분류하지 않습니다.

## 완료 점검

- [ ] 독립 작업과 생성 이점이 실제로 있었는가
- [ ] 최소 컨텍스트와 파일 소유권을 명시했는가
- [ ] 사용 가능한 모델만 선택했는가
- [ ] 루트가 결과 근거를 직접 검증했는가
- [ ] 하위 에이전트 부재를 저위험 작업의 인위적 차단으로 만들지 않았는가
