# 요구사항에서 Codex 실행 프롬프트 만들기

## 출력 언어

사용자가 출력 언어를 명시적으로 지정하면 해당 언어를 사용합니다. 지정하지 않으면 이 스킬이 만드는 모든 사용자 대상 출력, 문서, 프롬프트, 보고서, 계획, 스펙 및 기타 산출물을 한국어로 작성합니다. 제목, 섹션, 레이블, 표, 체크리스트, 다이어그램과 템플릿에도 같은 언어를 사용합니다. 코드, 명령어, 파일 경로, 식별자, API 이름, 모델 ID, 프로토콜 이름과 필수 고유명사는 번역하지 않습니다.

## 기본 흐름

1. 요청을 다시 표현하고 `확인된 사실`, `추정`, `조건`, `결정`, `열린 질문`으로 나눕니다.
2. 코드·문서·이력·테스트에서 답을 찾을 수 있는 내용은 사용자에게 묻지 않고 조사합니다.
3. 최신 외부 사실이나 지정 URL이 판단에 필요하면 브라우저로 공식·1차 자료를 확인합니다.
4. `setup-codex-prompt`의 등급을 적용합니다.
   - 빠른 작업은 문서를 만들지 않고 사용자의 현재 구현 요청에 따라 같은 작업에서 수행합니다.
   - 계획·민감 작업은 `.codex/prompts/active/<slug>.md` 한 파일에 수렴시킵니다.
5. 별도 Codex 작업이 유리하면 프롬프트 문서 안에 모델, 추론 강도, 선택 사유와 완전한 실행 프롬프트를 포함합니다.
6. 사용자가 계획을 수정하면 같은 프롬프트 문서를 갱신합니다. 새 초안 파일을 만들지 않습니다.
7. 사용자가 계획과 새 작업 시작을 명시적으로 승인하면 `start-implementation-thread`를 적용합니다.

## 문서 선택

기본 산출물은 단일 프롬프트 문서입니다.

별도 PRD 또는 기술 스펙은 다음 중 하나일 때만 만듭니다.

- 사용자가 해당 문서를 명시적으로 요청함
- 규제, 계약, 외부 리뷰 또는 조직 표준이 고정 형식을 요구함
- 여러 독립 작업에서 장기간 참조할 제품 범위나 공개 계약을 관리해야 함

별도 문서를 만들더라도 프롬프트 문서를 실행 진실의 진입점으로 유지하고 링크와 상태만 기록합니다. PRD 작성 후 기술 스펙 작성, 기술 스펙 작성 후 감사처럼 고정된 승인 체인을 강제하지 않습니다.

## 승인 규칙

- `수정해줘`, `구현해줘`, `실행해줘`는 빠른 작업의 실행 권한으로 인정합니다.
- 문서 작성 자체에 별도 승인을 요구하지 않습니다.
- 계획 작업에서 새 Codex 작업을 만들기 직전에 실행 계획·모델·추론 강도·프롬프트를 한 번 확인합니다.
- 삭제, 배포, 외부 전송, 결제, 권한 변경과 비가역 데이터 변경은 해당 행동 직전에 대상과 영향을 확인합니다.
- 최초 요청의 구현 의도를 무효화하지 않습니다. 다만 최초 요청만으로 새 작업 생성까지 승인한 것으로 확대 해석하지 않습니다.

## 완료 점검

- [ ] 사용자가 설명하지 않아도 확인 가능한 사실을 직접 조사했는가
- [ ] 빠른 작업에 문서와 승인 단계를 추가하지 않았는가
- [ ] 계획 작업의 실행 진실이 프롬프트 문서 하나에 모였는가
- [ ] 별도 문서는 실제 필요가 있을 때만 만들었는가
- [ ] 새 작업 생성 전 사용자에게 수정 가능한 모델과 추론 강도를 제시했는가
