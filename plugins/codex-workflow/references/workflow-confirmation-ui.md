# 버튼형 워크플로우 승인

## 출력 언어

사용자가 출력 언어를 명시적으로 지정하면 해당 언어를 사용합니다. 지정하지 않으면 승인 카드의 제목, 설명, 버튼, 후속 프롬프트와 폴백 문구를 한국어로 작성합니다. 코드, 명령어, 파일 경로, 식별자와 프로토콜 이름은 정확히 보존합니다.

## 사용 조건

다음 조건을 모두 만족할 때 `show_workflow_confirmation` 도구를 사용합니다.

- 사용자가 다음 단계의 진행 여부를 승인하거나 취소해야 합니다.
- 답이 `승인`과 `취소` 두 가지로 충분합니다.
- 아직 답하지 않은 열린 질문이 없습니다.
- 삭제, 배포, 결제, 외부 전송, 권한 변경처럼 Codex 네이티브 보안 승인을 별도로 요구하는 행동을 이 카드로 대체하지 않습니다.

가능성 검토, 대안 비교 또는 설계 토론에서 방향을 채택한 경우뿐 아니라 사용자가 처음부터 `구현해줘`, `고쳐줘`, `파일을 수정해줘`라고 요청한 경우도 버튼형 승인 대상입니다. 최초 요청은 목표와 의도로 기록하되, 아직 제시하지 않은 변경 범위의 실행 승인으로 보지 않습니다.

열린 질문이 하나라도 남아 있거나 세 가지 이상의 선택지가 필요하면 승인 카드를 띄우지 않고 기존 질문 규칙을 따릅니다.

## 호출 계약

`show_workflow_confirmation`에는 다음 값을 전달합니다.

- `title`: 승인 대상을 식별하는 짧은 제목
- `message`: 경로, 버전 또는 범위와 승인 영향을 포함한 설명
- `approveLabel`: 사용자가 승인 뒤 일어날 행동을 알 수 있는 버튼 문구
- `rejectLabel`: 기본값 `취소`
- `requestId`: 재시도 동일성이 필요할 때만 사용하는 안정 ID

모든 구현 승인 카드는 `message`에 변경 파일·동작·검증·제외 범위를 포함합니다. 구현 승인 카드를 호출한 턴에는 파일을 수정하거나 상태를 바꾸거나 구현·검증 명령을 실행하지 않습니다.

승인·취소 뒤 게시되는 후속 메시지는 카드에 보인 `title`과 `message`에서 서버가 결정적으로 만듭니다. 보이지 않는 별도 프롬프트를 전달하지 않습니다.

예시:

```json
{
  "title": "기술 스펙 승인",
  "message": "표시된 기술 스펙 v1을 기준으로 새 구현 작업을 시작합니다.",
  "approveLabel": "승인하고 시작",
  "rejectLabel": "취소"
}
```

도구 호출 뒤에는 추가 설명을 길게 붙이지 않고 현재 턴을 끝냅니다. 버튼이 후속 메시지를 게시하면 기존의 별도 사용자 승인 메시지와 같은 것으로 처리합니다.

범위를 제시한 턴보다 뒤의 별도 승인 메시지를 받은 후에는 카드에 표시한 범위를 다시 확인하고 구현·검증을 진행합니다. 취소 후에는 현재 단계에 머물며 구현하지 않습니다. 승인된 범위를 넘어서는 변경이 새로 필요해지면 별도 범위 확장 승인을 받습니다.

## 폴백

호스트가 MCP Apps UI를 렌더링하지 않으면 도구의 `content`에 포함된 제목, 설명과 답변 문구를 대화에 그대로 제시합니다. 호스트 호환성은 별도 통합 테스트에서 확인하며, 확인 전에는 UI 렌더링을 보장했다고 보고하지 않습니다.
